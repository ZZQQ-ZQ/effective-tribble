# 会话唯一事实源

> **核心原则**：一个会话，一份源。新信息不覆盖旧信息——旧信息进废弃区。冲突以最新确认指令为准，但必须指出变化。

## 文件位置

```
memory/session-truth-YYYY-MM-DD.md
```

每次新会话开始时创建，会话内持续更新同一文件。

## 六大分区（固定结构·不可缺）

### 一、已确认的稳定事实
角色、项目、平台、场景、空间关系等不会频繁变化的底层信息。
格式：`- 事实描述（来源/确认时间）`

### 二、用户长期偏好与硬性规则
从 SOUL.md/AGENTS.md/USER.md 摘录当前会话涉及的核心规则。
格式：`- 规则摘要（来源文件）`
注：不全文复制，只摘录与本会话任务直接相关的规则。

### 三、已经完成的工作
已定稿、已输出的内容，附状态标记。
格式：`| 工作项 | ✅/🔄/⬜ | 备注 |`

### 四、重要决策及其理由
每次推翻旧结论、确认新版本、做出关键选择时记录。
格式：`| 决策 | 理由 | 时间 |`
冲突处理：如新决策与旧决策矛盾→旧决策移至"已废弃"，新决策写入此处，同时标注"⚠️ 推翻旧决策：[原决策摘要]"

### 五、当前有效的最新版本
所有"当前版本"的集中索引。
格式：`- [类别] 文件名/版本号（更新时间）`

### 六、尚未解决的问题和下一步任务
任何未完成、未确定、待推进的事项。
格式：`🔄/⬜ 事项描述`

## 自动更新触发条件

以下情况**必须**更新事实源：

| 触发事件 | 更新分区 | 操作 |
|---------|---------|------|
| 规则被修改/推翻 | 二、四、七 | 旧规则→废弃区，新规则写入，记录决策理由 |
| 某个段落/提示词定稿 | 三 | 状态标记改为✅ |
| 导演确认新版本 | 四、五 | 记录决策+更新版本索引 |
| 新信息出现，与旧信息冲突 | 四、七 | 先指出变化→旧信息→废弃区→新信息写入 |
| 完成一个重要阶段 | 全部 | 更新所有分区+输出快照 |
| 导演说"记住这个" | 按分类归属 | 同 AGENTS.md 分类规则 |

## 冲突检测（执行复杂任务前强制）

每次执行以下操作前，先检查唯一事实源是否存在冲突：
- 写提示词/分镜
- 修改已有定稿
- 应用新规则

检测三步：
1. 读当前事实源
2. 逐项对比新指令与已有记录
3. 发现冲突→先指出"⚠️ 冲突：[旧信息] vs [新指令]"→导演确认→更新

## 阶段快照格式（≤300字）

完成重要阶段后输出：

```
📊 会话状态快照 [YYYY-MM-DD HH:MM]

已完成：X段定稿
进行中：[当前阶段简述]
待解决：[最多3项]
当前版本：[关键版本号]
最近决策：[最近1-2条]
下一步：[下一步行动]
```

## 废弃区规则

1. 任何被推翻/替换的旧信息→移至第七分区
2. 标注废弃原因+废弃时间
3. 废弃区内信息**绝不**与当前有效规则混用
4. 格式：`~~原信息~~ → 废弃原因（废弃时间）`

## 配合使用

- **SOUL.md / AGENTS.md**：永久规则源。session-truth 只摘录当前会话相关部分，不全文复制。
- **MEMORY.md**：跨会话长期记忆。session-truth 是单会话的临时状态，重要决策在会话结束后提炼入 MEMORY.md。
- **memory/YYYY-MM-DD.md**：每日原始日志。session-truth 是结构化摘要，不替代每日日志。
